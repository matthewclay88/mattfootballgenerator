# Weekly Fantasy Football Projection Simulator

Pick a player, sorted by position, and get a **Monte Carlo simulation**
of their fantasy output for every week of the season &mdash; floor,
median, ceiling, and boom/bust rates &mdash; run 50&ndash;250 times per
week right in your browser.

It's built to be **free to host**: a GitHub Action refreshes the data
on a schedule and commits it to the repo; the site itself is static
(plain HTML/CSS/JS) and runs the simulation client-side, so GitHub
Pages can serve the whole thing with no backend server.

## How it works

```
scripts/fetch_data.py       ──►  docs/data/players.json  ──►  docs/index.html (GitHub Pages)
 (nflverse + FantasyPros ECR)      (committed by the                (loads the JSON, runs the
                                    GitHub Action)                   simulation in JS)
```

1. **`scripts/fetch_data.py`** pulls each offensive player's last two
   seasons of weekly logs from [nflverse](https://github.com/nflverse/nfl_data_py)
   (via `nfl_data_py`), fits simple statistical distributions to their
   volume (carries/targets/attempts), efficiency (YPC, YPR, yards per
   attempt), and scoring rates (TDs, INTs, fumbles), and pulls the
   current season's schedule for weekly opponents and bye weeks.
2. It also pulls **Expert Consensus Rankings** from the official
   [FantasyPros API](https://www.fantasypros.com/api-data/) &mdash;
   real rankings aggregated across 130+ fantasy analysts, by
   position and scoring format &mdash; used to sort the sidebar and
   show each player's consensus rank. See **FantasyPros API key**
   below to set this up (it's free).
3. Everything is written to `docs/data/players.json`.
4. **`.github/workflows/update-data.yml`** runs that script on a
   schedule (default: every Tuesday morning UTC, after Monday Night
   Football stats are final) and commits the refreshed JSON.
5. The static site in `docs/` loads that JSON and, when you pick a
   player, runs the actual Monte Carlo simulation (Negative
   Binomial for volume, Normal for efficiency, Poisson for
   touchdowns/turnovers) entirely in the browser &mdash; no server
   round-trip.

## Getting started

### 1. Get a free FantasyPros API key

1. Go to <https://secure.fantasypros.com/api-keys/request> and
   request a **Free** key (no cost, meant for exactly this kind of
   personal project &mdash; you may need a free FantasyPros account
   first).
2. You'll get a key by email. Keep it handy for step 4.

This step is optional in the sense that the site still works without
it (players just sort alphabetically instead of by expert rank), but
it's what gets you real expert-consensus rankings instead of a
placeholder order.

### 2. Create the GitHub repo

If you don't already have this project in a repo:

```bash
cd fantasy-sim        # the folder you unzipped
git init
git add .
git commit -m "Initial commit"
```

Then on GitHub: click **New repository** (top right &rarr; the `+`
icon &rarr; **New repository**), give it a name like `fantasy-sim`,
leave it empty (no README/gitignore &mdash; you already have those),
and click **Create repository**. GitHub will show you a remote URL;
use it here:

```bash
git branch -M main
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

### 3. Add your API key as a repo secret

Your key should never be committed to the repo itself &mdash; it
goes in GitHub's encrypted secrets store instead:

Repo **Settings &rarr; Secrets and variables &rarr; Actions &rarr;
New repository secret**. Name it exactly `FANTASYPROS_API_KEY` and
paste in the key from step 1. Save.

### 4. Turn on GitHub Pages

Repo **Settings &rarr; Pages &rarr; Build and deployment &rarr;
Source: Deploy from a branch &rarr; Branch: `main`, folder: `/docs`
&rarr; Save**. Your site will be live at
`https://<your-username>.github.io/<your-repo>/` within a minute or
two.

### 5. Let the Action populate real data

The repo ships with a small **synthetic sample dataset**
(`docs/data/players.json`, generated by
`scripts/generate_sample_data.py`) so the site isn't empty on first
load. To replace it with real data:

- Go to the **Actions** tab &rarr; you may need to click **"I
  understand my workflows, go ahead and enable them"** the first
  time &rarr; select **Update player data** &rarr; **Run workflow**
  to trigger it manually, or
- Just wait for the Tuesday schedule, or
- Run it locally:

  ```bash
  export FANTASYPROS_API_KEY=your_key_here
  pip install -r scripts/requirements.txt
  python scripts/fetch_data.py
  git add docs/data/players.json
  git commit -m "Refresh player data"
  git push
  ```

Once the Action runs successfully, refresh your GitHub Pages URL and
you should see real players sorted by real expert consensus rank.

## Scoring formats

The site supports Standard, Half PPR, and Full PPR &mdash; pick one
from the dropdown above the chart. It's applied at simulation time,
not baked into the stored data, so switching formats just re-runs the
simulation instantly. The expert rank shown next to a player's name
also switches to that format's FantasyPros ranking.

## About the FantasyPros API tier

The **Free** tier (what `FANTASYPROS_API_KEY` above gets you) is
meant for building and personal/non-commercial use, with sample data
and a generous daily call limit &mdash; exactly this project's use
case. `fetch_data.py` makes 12 calls per run (4 positions &times; 3
scoring formats), well within that limit, and only runs on the
weekly schedule (or on demand), so you won't come close to any rate
limit. If FantasyPros ever changes the free tier's terms, check
<https://www.fantasypros.com/api-data/> for current pricing.
